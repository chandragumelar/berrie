# Fondasi aplikasi Berrie

Scaffold belum dapat digunakan untuk transaksi. UI dan data contoh tetap di `../berrie-site/`; integrasi UI mengikuti T-06 setelah fondasi dan izin siap.

Dengan Node 22 dan npm: `npm ci --legacy-peer-deps`, `npm run dev`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. `npm run test:browser` menjalankan tes Chrome lokal melalui Playwright; konfigurasi saat ini memakai Chrome di `/Applications/Google Chrome.app`. `.env.example` tidak berisi rahasia. Lockfile mencatat versi terpasang.

`src/domain` mencakup kalkulasi dan snapshot awal, `src/storage` berisi primitive Dexie berversi, pemeriksaan revisi/urutan dan Web Locks. Ini belum merupakan API transaksi berizin: T-04 harus memvalidasi identitas, kebijakan, permit dan perangkat aktif, dan command bisnis harus memvalidasi seluruh invariants dalam transaksi. Web Locks yang tidak tersedia menyebabkan penolakan, bukan fallback tanpa lock. Checkpoint/staging awal bukan backup terenkripsi atau restore produksi; tidak mengaktifkan database staging. Lihat tasks untuk pekerjaan dan batas yang tersisa.

`stageSnapshot(db, input)` menerima `unknown`, memvalidasi checkpoint schema 1 dan hubungan receipt/state/event/sequence sebelum menulis atomik ke database staging yang masih kosong. Fungsi tidak mengaktifkan staging atau mengubah database sumber. Nilai state baru dapat menggunakan envelope `{ recordType: 'settlement', schemaVersion: 1, settlement }` atau `{ recordType: 'refund-history', schemaVersion: 1, settlement, refunds }`. Gunakan `createSettlementRecord` dan `createRefundHistoryRecord` di `src/domain/business-record.ts`; keduanya memvalidasi dan menyalin input. Commit memvalidasi nilai bertanda sebelum menulis; checkpoint/staging memvalidasi state terkini dan setiap nilai state dalam payload receipt historis. Penanda/versi yang tidak dikenal ditolak. Record generik lama tanpa `recordType` tetap diterima dengan kontrak storage lama, termasuk objek dengan `kind`; isi bisnisnya belum divalidasi. Tidak ada penebakan tipe atau migrasi data lama. Validasi konsistensi bukan bukti autentisitas, otorisasi, atau perlindungan dari manipulasi checkpoint yang terkoordinasi.

`planStockDebits(input)` di `src/domain/stock.ts` menerima `unknown`: `{ rows: [{ rowId, skuId, groupId, qty }], balances: [{ groupId, balance }] }`. ID baris dan grup saldo harus unik dan tidak kosong; SKU boleh berulang. Qty integer 1–999, saldo integer aman ≥0, dan setiap grup baris harus tersedia. Input tidak sah atau overflow melempar error; daftar kosong menghasilkan rencana kosong. Hasil sukses mengurutkan grup dan sumber berdasarkan ID serta memuat kebutuhan, saldo sebelum/sesudah dan sumber; kekurangan menghasilkan `{ ok: false, shortages }` tanpa debit parsial. Contoh dua baris rasa berbeda masing-masing qty1 dalam grup saldo50 menghasilkan kebutuhan2 dan sisa48. Qty mencakup unit gratis/promo; tidak ada konversi, resep atau stok topping.

Ini hanya perhitungan calon konfirmasi, tidak mengubah saldo. Pemanggil kelak wajib memilih hanya unit draft yang belum confirmed dan memvalidasi ulang saldo serta revisi dalam transaksi atomik bersama efek bisnis lain. Fungsi ini tidak membuktikan debit aktual, idempotensi, retry atau integrasi storage.
